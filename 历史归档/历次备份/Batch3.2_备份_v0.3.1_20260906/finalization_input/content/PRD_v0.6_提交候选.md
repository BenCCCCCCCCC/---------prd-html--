# 网易云音乐｜推荐控制链路优化

产品需求文档 · v0.6 提交候选 · 2026-09-06

## 01｜目标与范围

在现有推荐与播放链路中整合偏好控制，让用户明确设置“想听什么、少听什么、影响多久”，并能取消、撤销和恢复。[S01]

用户目标是减少纠偏步骤、理解操作后果；产品目标是验证推荐体验能否改善，同时控制操作负担和内容收窄风险。留存与信任是待验证的业务收益，不预设增长结果。

| 需求 | 优先级 | 本期范围 |
| --- | --- | --- |
| R03 推荐控制链路 | P0 | 想听、少推、影响范围、撤销、已保存偏好管理。 |
| R04 临时收听 | P1 | 当前设备普通收听的长期学习隔离、状态提示、到期提醒与关闭。 |
| R05 历史推荐影响管理 | P2 后续 | 定义事件排除与依赖，不实现完整操作。 |
| R06 手势快捷入口 | P2 实验 | 保留方案和验证条件；本期使用可见入口。 |
| R07 自然语言调整 | P2 实验 | 本地解析、可编辑候选与用户确认；不接真实模型。 |

非目标：重做推荐模型、首页与评论，新增账号、版权、支付、音频服务或通用 Agent。

本文件供产品、设计、客户端、推荐/数据及测试评审。实现参考为指定 Figma 播放页与代码原型；文档和原型分别标注版本。

## 02｜需求依据

当前依据为既有产品观察、课程反馈、公开资料及20个模拟问卷案例；尚无真实问卷原始数据。下列诉求是待验证假设，不能用模拟案例估计需求发生率。[S01–S04]

| 依据 / 现象 | 问题推导 | 方案与验证 |
| --- | --- | --- |
| 既有观察记录控制入口分散。 | 用户可能找不到纠偏路径；入口难找与调整无效需要分别判断。 | R03聚合入口；分别测发现、完成和调整后体验。 |
| 精准偏好、探索、控制新手的诉求不同。 | 相同使用频率不代表相同推荐需求。 | 按意图与熟练度分层，再与频率、强度交叉分析。 |
| 临时收听不一定代表长期兴趣。 | 情境性行为可能被用于长期学习；实际影响需事件证据核验。 | R04提供隔离控制；先验隔离正确性，再测理解与长期体验。 |
| 一句话可同时表达多个条件。 | 可能减少逐项选择，也可能增加解析与确认成本。 | R07与手动调整对照，不以使用AI本身作为收益。 |

推荐不合意也可能来自版权或候选池变化、热点、兴趣改变、网络失败。需求验证需区分这些替代解释。既有观察对应2026-08-28的产品画面；W3原报告与公开反馈逐条来源尚待补齐。[S01]

## 03｜用户分层口径

频率、强度、新老程度、功能熟练度、当前意图与情境分别记录，不把“高频用户”直接视为一种需求。[S02]

| 维度 | 定义 | 分析边界 |
| --- | --- | --- |
| 推荐频率 | 分析日前28个完整自然日中，从推荐来源至少开始播放一次的天数；高频≥16天，中频4–15天，低频1–3天，0天单列。 | 这是推荐使用频率，不是App打开频率。观察不足28天时单列，不按比例外推。 |
| 收听强度 | 全部音乐收听活跃日的平均实际收听分钟数；分为<30、30–<60、60–<120、≥120，排除暂停与缓冲。 | 保留连续值；每天短时使用不等于重度。 |
| 新老程度 | 首次可用音乐播放距今的完整天数：≤7天新手期，8–30天熟悉期，>30天存量期；注册时间另记。 | 使用时长不代表推荐控制熟练度。 |
| 推荐依赖 | 推荐来源播放开始次数÷全部音乐播放开始次数。来源在队列创建时记录。 | 至少20次可识别播放才分层；不足、分母为0单列，不因页面跳转改来源。 |
| 功能熟练度 | 无提示完成找少推入口、解释影响范围、撤销三项任务；记录结果与用时。 | 失败也可能来自界面，不归咎于用户能力。 |
| 意图与情境 | 本轮保持熟悉还是探索；是否借设备、共同收听或临时背景音乐。 | 先记录当下任务，不凭年龄、职业、单次跳过或曲风作永久分类。 |

以上为初始招募和分析口径，尚未校准。16天取自每周约4天的候选切点；统计日界采用账号固定时区，缺失时统一UTC+8并记录。每项保留分子、分母、窗口、来源及缺失原因；阈值调整需版本记录和相邻切点敏感性检查，不能事后挑选有利分组。

## 04｜典型任务与交叉分析

精准偏好与探索描述当前意图；控制新手描述熟练度；临时收听描述情境。四者可以叠加。

| 任务 | 用户诉求与风险 | 产品响应 |
| --- | --- | --- |
| 精准偏好 | 知道想听的方向，不希望探索打断任务。 | 提供熟悉、方向标签与少推；验证能否准确表达。 |
| 探索发现 | 希望发现新内容，但仍有不想听的对象。 | 新鲜程度与内容方向独立；探索不等于随机，也不解除黑名单。 |
| 控制新手 | 找不到入口，或不理解“本次”的范围。 | 可见文字入口、默认仅本次、明确结果与撤销。 |
| 临时情境 | 当前普通收听不代表自己的长期兴趣。 | 隔离状态跨受控来源持续；主动收藏等操作仍保留。 |

| 交叉组合 | 典型情境 | 验证问题 |
| --- | --- | --- |
| 高频＋短时＋精准偏好 | 每天十分钟通勤。 | 一次调整是否比继续跳歌更费事？ |
| 高频＋长时＋探索 | 希望新内容，但反感某音乐人。 | 探索与少推能否并存，内容是否过窄？ |
| 低频＋长时＋熟练 | 28天仅听1–3天，每次数小时。 | 低频用户能否同样找到入口，一次调整能否覆盖任务？ |
| 存量用户＋控制新手 | 使用多年，从未设置影响范围。 | 是否仍需解释，首次使用能否独立完成？ |
| 任意频率＋临时情境 | 陪他人听歌或临时播放。 | 跨页面仍能看见保护吗，是否误认为历史被删除？ |

首轮计划8个真实测试席位，覆盖上述组合，一人可覆盖多个维度。记录任务结果与原话，再决定补充访谈或问卷；该人数用于覆盖测试情境，不代表市场样本量。

## 05｜竞品与差异化

主竞品为QQ音乐、Apple Music；Spotify为补充参照。以下沿用2026-09-05资料快照，产品后台和同版本实机路径未获内部验证。

| 产品 / 来源 | 借鉴点 | 本方案的选择 |
| --- | --- | --- |
| QQ音乐：TME 2025年第四季度业绩资料披露自然语言Agent任务，涉及音乐发现及购买。[W01] | 显式意图可直接成为任务输入。 | 先做手动控制；R07只解析条件，不购买或代替推荐排序。 |
| Apple Music：Use Listening History及Focus设置。[W02] | 用户控制收听历史是否影响推荐。 | 在播放链路提示保护；分别定义显式操作与普通行为，不假定竞品事件粒度相同。 |
| Spotify：从taste profile排除单曲或歌单。[W03] | 降低收听对画像的影响，不等同于屏蔽歌曲。 | R05面向具体历史事件；不将“减少影响”理解为删除数据或模型遗忘。 |
| 网易云既有观察：风格推荐、负反馈和黑名单已存在。[S01] | 优先整合已有能力。 | 在原推荐/播放链路增加控制，不另建推荐中心。 |

本期选择播放链路内的控制弹层。只改文案不能覆盖影响范围；独立中心离播放任务较远；完全对话式方案增加解析与确认成本，因此仅作R07实验。完整取舍见§19。

## 06｜R03：入口、字段与提交

推荐页工具区及对应播放页提供轻量入口，不按高低频隐藏。播放页入口显示“调整本次推荐偏好”，总面板标题为“调整推荐偏好”；两者对应同一R03功能。首次说明可关闭，不强制弹出或按跳过次数反复提示。歌曲“更多”保留即时少推路径。

| 控制项 | 默认与含义 | 规则 |
| --- | --- | --- |
| 新鲜程度 | 熟悉 / 平衡 / 探索，单选，初始平衡。熟悉偏向已知方向，探索提高新内容机会。 | 再次打开显示有效设置；不新增热度或新歌时效维度。 |
| 内容方向 | 曲风 / 情绪 / 场景 / 语种 / 主题；初始不选标签。 | 跨分类最多3项；第4项提示上限，不自动替换。标签为软偏好。 |
| 少推对象 | 当前歌曲 / 音乐人 / 风格，单次选择一个对象。 | 锁定打开时的歌曲快照；可再次进入添加其他对象。风格无法可靠识别时禁用该项。 |
| 影响范围 | 每次新建调整默认仅本次；可选保存为长期偏好。 | 只保存实际修改字段；仅切换范围不写入默认值。保存已有本次方案需明确确认差异。 |
| 临时收听 | 与保存范围独立。 | 确认前仅修改草稿；打开弹层不重置原有保护。 |
| 已保存偏好 | 查看本方案保存的长期方向与少推项；支持移除、清空。 | 清空需确认；不删除平台画像、红心、歌单或黑名单。 |

子页返回/完成保留草稿；总面板取消/关闭丢弃草稿；“确认调整”才提交。无有效变更时禁用确认。已有本次方案转长期时，列出差异，并要求勾选保存确认。校验失败保留输入并定位字段。

同一标签既想听又少推时，要求用户消除冲突，不静默代选。想听民谣与少推某民谣音乐人可以并存。黑名单独立生效。长期提交清除同字段的旧会话覆盖；冲突校验以提交后的完整状态为准。

本期原型的黑名单为只读预置项；不包含新增、删除管理。真实产品管理入口属于集成依赖。

## 07｜推荐与降权规则

先检查内容可用性和黑名单，再合并明确偏好，最后排序。同字段采用“会话覆盖→本方案长期设置→默认值”；会话未改字段继承长期设置。同一少推对象不叠加惩罚。

普通播放或跳过不能自动改写明确设置。长期画像与近期行为的实际融合由推荐团队验证；黑名单、作用范围和隔离事件是硬边界。[S02]

### 原型排序参数

```text
可用候选 = playable=true 且不在预置黑名单中的歌曲
有效方向 = 会话覆盖项 ?? 已保存长期项 ?? 默认值
score = baseScore + 0.30 × positiveMatch
        + 0.20 × freshnessSign × (2 × novelty − 1)
        − 0.60 × negativeMatch
按score降序；同分按trackId升序。
```

| 变量 | 定义 |
| --- | --- |
| baseScore / novelty | 预置0–1值，分别表示基础排序与用户新鲜度；novelty不是发布时间。 |
| positiveMatch | 命中的有效正向标签数÷有效正向标签总数；无标签时为0，各类别均为软匹配。 |
| freshnessSign | 熟悉=-1，平衡=0，探索=1。 |
| negativeMatch | 命中任一有效少推对象为1，否则为0；多次命中仍只惩罚一次。 |
| 失效 | 会话少推随会话结束失效；长期少推由用户移除；本期无额外7天或30天衰减。 |

上述权重仅用于可重复的本地演示，不代表真实曝光下降比例。生产参数需通过候选可用性、离线重排、效果与多样性评估后确定。

少推仍可能出现；黑名单内容不进入自动推荐，不限制手动搜索/播放。结果不足时展示可用结果或无结果说明，不解除黑名单或恢复隔离行为，不强制切掉当前歌曲。

## 08｜保存范围与临时收听

R03控制本轮明确设置保存多久；R04控制普通收听是否用于长期学习。

| 保存范围 / 临时收听 | 明确设置 | 普通播放、时长与跳过 |
| --- | --- | --- |
| 仅本次 / 关闭 | 会话生效 | 正常参与长期学习。 |
| 仅本次 / 开启 | 会话生效 | 保护期间不参与长期学习。 |
| 长期 / 关闭 | 保存到长期偏好 | 正常参与长期学习。 |
| 长期 / 开启 | 仍保存到长期偏好 | 保护期间不参与长期学习。 |

“仅本次”本身不是画像保护。长期偏好与临时保护可以同时开启，因为两者处理不同对象。

| 行为 | 保护期间处理 |
| --- | --- |
| 普通播放、实际时长、普通跳过 | longTermEligible=false；其派生的音乐人、曲风、情绪等特征也不能进入长期学习。 |
| 红心、收藏、加歌单、关注 | 正常保存明确操作；平台实际学习策略待集成确认。 |
| 仅本次少推 | 只写会话，不写长期偏好。 |
| 明确选择长期的少推/方向 | 按选择保存；不能由普通跳过或AI默认升级为长期。 |
| 黑名单 | 保持独立强约束。 |
| 分享、下载、搜索文字、浏览 | 不新增“强喜好”推断，也不视为长期偏好授权。 |

R03覆盖每日推荐、心动/心动模式、私人漫游及后续自动队列；不改搜索排序和手动歌单顺序。R04跟随当前设备受控播放器，同时覆盖搜索结果手动播放、用户歌单与手动选曲；页面切换不结束保护。

未知本地音频、播客/直播、投屏设备及第三方播放器不在首版范围。来源不明的音乐事件先隔离待核验；生产接入逐项验证来源覆盖。

## 09｜会话生命周期

“本次”是一段当前设备收听会话，不按自然日或歌单划分。会话偏好与临时保护分别计时。30分钟、4小时为初始参数，配置见`product-config.json`。

| 条件 | R03会话偏好 | R04临时保护 |
| --- | --- | --- |
| 首次确认有效调整 | 创建会话，记录开始时间与版本。 | 明确开启并确认后才生效；只影响之后的行为片段。 |
| 继续听歌或修改设置 | 更新覆盖项，不延长最初4小时上限。 | 持续保护，不因切歌、后台播放或换页结束。 |
| 暂停且30分钟无收听 | 清除会话覆盖，恢复已保存长期设置。 | 进入待确认，继续保护。 |
| 达到4小时 | 结束会话覆盖，长期设置不变。 | 提醒并继续保护；用户选择继续4小时或关闭。 |
| 主动结束/关闭 | 结束本次调整只移除会话覆盖。 | 仅关闭后的事件恢复正常，已隔离片段不补回。 |
| 刷新或崩溃恢复 | 读取绝对时间并校验失效。 | 恢复设备保护状态；未知状态保守隔离。原型使用同标签页恢复。 |
| 切换账号/设备 | 不共享会话。 | 不把旧事件归入新账号；其他设备不自动跟随。 |

采用到期确认，而非静默恢复学习：减少忘记关闭的风险，同时维持用户已选择的保护。确认负担作为后续测试项，取舍见§19。

播放页、推荐页和迷你播放器按各自场景显示保护状态；待确认提示“已到提醒时间，当前仍不用于长期推荐”。搜索或歌单场景通过迷你播放器提示。关闭后说明只有后续普通收听恢复参与。

后台定时器延迟时，在页面恢复、播放或写事件前重新校验时间。保护闲置从最近收听或保护开启的较晚时点计算，避免计入开启前的暂停时间。测试工具可推进时间，不作为音乐产品入口。

## 10｜页面与操作流程

```text
推荐页 / 对应播放页
  └ 调整推荐偏好
     ├ 本次想听：新鲜程度＋内容方向
     ├ 不想听：少推对象＋黑名单说明
     ├ 影响范围：仅本次/长期＋临时收听
     └ 已保存偏好：查看、移除长期设置
播放页 / 迷你播放器：生效摘要、保护状态、结束本次调整
R07实验入口：候选预览→草稿，不替代主流程
```

| 操作 | 结果 |
| --- | --- |
| 子页返回/完成，Esc或浏览器返回 | 回上一层并保留草稿，不直接离开项目。 |
| 总面板取消、遮罩关闭或Esc | 丢弃草稿，回原页面，焦点回触发入口；手势不是唯一出口。 |
| 总面板确认 | 进入提交状态，阻止重复操作；失败保留草稿。 |
| 更多→即时少推→确认 | 独立短草稿，默认仅本次；无需经过其他设置页，成功可撤销。 |
| 成功→撤销 | 按本笔operationId恢复修改字段，不回退播放进度或独立收藏。 |
| 进入已保存偏好 | 独立事务。存在脏草稿时提示放弃本轮修改，默认留在当前面板；不得自动提交。 |
| R07采用候选 | 回总面板草稿；只有最终确认才生效。 |

所有弹层提供可见返回/关闭。新增交互使用可操作组件；原播放器上下文按指定Figma画面还原。背景、原有非本期区域及新增功能的实现边界在原型旁标注。

## 11｜服务流程与执行一致性

目标集成涉及客户端、偏好控制、推荐、画像与数据服务；本地原型仅模拟这些边界。

![多角色正向、取消、失败与撤销流程](../design/flow_roles.png)

“设置已保存”与“推荐已展示”分两阶段记录，分别对应`preference_applied`和`recommendation_rendered`。结果携带revision，迟到旧结果不得覆盖新版本。

每笔操作记录beforePatch、afterPatch及字段版本。撤销绑定本笔operationId；后续相关字段变化或会话终止时，按既有资格拒绝旧撤销，不覆盖新状态。撤销不回退已发生的播放、曝光或独立收藏，也不补回保护期间的学习事件。

成功提示显示10秒；提示消失不终止撤销资格，持久恢复入口保留至下一次相关变更或会话终止。撤销成功替换旧回执并移除本条撤销按钮；失败或冲突不显示成功。结果就地反馈，不自动滚动整页。

## 12｜异常、数据与依赖

| 情况 | 处理 | 验收重点 |
| --- | --- | --- |
| 提交超时或结果未知 | 保留播放和草稿；使用原operationId查询/重试。 | 不重复写入，不伪报已生效。 |
| 设置保存成功、推荐刷新失败 | 分别说明保存与刷新状态，支持重试；按关闭/开启/待确认显示真实保护状态。 | 不把保存成功当推荐已展示。 |
| 无结果或标签不足 | 展示可用结果或无结果，保留当前播放。 | 不绕过黑名单；技术失败不计主动跳过。 |
| 打开后歌曲变化 | 仍少推打开时锁定的对象。 | 对象名与操作目标一致。 |
| 并发或迟到结果 | 按revision及字段版本校验。 | 旧请求、旧撤销不覆盖新设置。 |
| 一首歌中途切保护 | 按切换时间分段计算时长。 | 不能以结束时状态归类整首歌。 |
| 离线、来源或身份不明 | 按事件发生时标记处理，无法确认则隔离。 | 离线上传、跨账号/设备无旁路。 |
| 交互负担或内容收窄 | 保留快捷少推；观察完成时间、取消、理解及多样性。 | 不为提升指标解除屏蔽或保护。 |
| 隔离减少学习样本 | 观察适应速度和长期体验。 | 不以业务效果为由绕过用户选择。 |
| AI失败、成本或时延风险 | 回退手动选择；真实服务另行确认预算、隐私与时延。 | 核心流程不依赖AI成功。 |

自由输入仅在内存处理；不进入URL、持久缓存、事件导出或远程统计，离开原型或刷新后清除。技术字段放在研发/测试工具中，不进入普通结果提示。托管访问日志另行核验，不作“服务器不留日志”的保证。

真实集成需核验事件、派生特征和画像三个环节。临时保护不是匿名模式、删除历史或已训练模型遗忘；其他数据用途以实际政策为准。

待决：刷新失败的“继续”目前仅返回播放器，是否同时收起详细失败提示尚未定义；200%文字下反馈占位需真机验证。两项不由前端自行改变业务含义。

## 13｜R07：自然语言候选

用于表达多条件偏好。当前原型为本地规则解析，真实模型接口未启用。[W04–W07]

```text
输入→解析→结构/权限/冲突校验→可编辑候选
→采用到草稿→总面板确认→确定性执行
```

| 项目 | 约束 |
| --- | --- |
| 输入 | 最多200个Unicode字符；仅带当前示例歌曲、标签白名单、draftRevision，不提供真实历史。 |
| 状态 | ready / needs_clarification / unsupported；适配器失败为error，不冒充有效候选。 |
| 可修改候选 | freshness、positiveTagIds、negativeTargets；null不修改，空数组仅在明确清除时表示清空。 |
| 权限建议 | scopeSuggestion、isolationSuggestion仅建议用户去对应设置确认，不直接改变范围或保护。 |
| 禁止 | 曲库外对象、未知标签、额外字段、自动执行、拉黑、删除历史及修改画像。 |
| 表达 | 同值显示“与当前设置一致”；未提及显示“保持不变”；未知片段要求确认，不显示未经校准的数值置信度。 |
| 失败/取消 | 保留输入至关闭；可改用手动调整。取消、离开或迟到结果不得写入草稿。 |

“想听安静的中文歌，熟悉的多一点”生成熟悉＋安静＋中文候选；“以后都这样推荐”提示手动选长期；“这周不要摇滚”要求澄清，不映射为本次。双重否定、冲突、未知曲风和强屏蔽要求不得硬猜。

分别评估结构、语义、权限和任务完成。Schema通过不代表意图理解正确。现有40条合成用例用于本地解析回归；真实模型评估需记录模型、Prompt、词典版本及逐类结果、时延、成本和用户修正，不能把开发集通过率当作泛化表现。

## 14｜指标定义

按结果、过程、反向/诊断分类；分母为0记N/A。真实业务效果尚待验证。

| 指标 | 计算与窗口 | 判断 |
| --- | --- | --- |
| 结果：调整后有效收听率 | 应用后30分钟内前5次推荐来源播放中，有效播放次数÷实际可观测开始次数。开始后的主动跳过计分母；未开始取消、技术失败单列。 | 期望提高；同步报告0次及不足5次的会话。仅用于调整用户内诊断，不单独证明因果。 |
| 结果：实验主指标 | 推荐来源有效收听秒数总和÷所有随机分配合格用户日；无播放用户日计0。 | 提高且护栏稳定才支持扩大；随机化和分析均按用户。 |
| 结果：早跳率 | 同一窗口内实际收听不足30秒主动跳过次数÷推荐播放开始次数。 | 通常期望下降；探索任务需另行解释。 |
| 过程：入口点击率 | 同次可见曝光内点击会话数÷可见曝光会话数；可见为面积≥50%且持续1秒。 | 反映发现与兴趣，不等于需求价值；需控制教学影响。 |
| 过程：完成率/用时 | 成功应用的编辑会话÷打开编辑会话；从打开计时至成功，取消和失败单列。 | 期望完成率提高、用时降低；无变更提交不计成功。 |
| 反向：撤销/恢复 | 应用后30分钟内撤销或结束本次的操作数÷成功应用数。 | 按原因分析，不把正常任务结束等同于不满。 |
| 反向：多样性/总体验 | 首20条可用推荐的音乐人数及归一化曲风分布，同时观察总有效收听和退出。 | 候选池、定义与窗口固定；防止纠偏使内容过窄。 |
| 反向/正确性：保护泄漏 | 保护期间仍可用于长期学习的隐式事件数÷保护隐式事件数，并检查派生特征。 | 必须为0；发现一例即调查并停止错误写入。 |

有效播放暂取实际收听≥30秒，仅统计曲长≥60秒的音乐。此口径及曝光阈值均为初始测量参数；生产上线先确认平台定义并冻结，再采基线。保护泄漏属于不可与点击收益交换的正确性门槛。

## 15｜埋点与实验

链路：入口曝光→打开编辑→提交→设置应用→结果展示→播放片段→撤销/关闭。共用eventId、occurredAt、deviceSessionId、operationId、revision、sourceScene、environment；真实实验另带匿名用户标识、分组与分桶版本。触发和去重详见`events.spec.json`。

临时收听开启率不代表隔离有效；缺少真值的“会话后异常推荐率”不作直接验收指标。先验泄漏，再用任务研究与受控实验判断推荐偏移。

| 实验要素 | 计划 |
| --- | --- |
| 方案 | 先比较原交互与R03；R04完成正确性和理解验证后，再比较R03与R03＋R04。R07单独比较手动与自然语言。 |
| 对象与样本 | 按账号固定分组，设备不跨组。首次符合资格且未展示新功能时分桶，不按是否点击纳入。根据基线方差、最小业务差异Δ、流失率估算用户级样本量。预分层使用实验前28天频率、强度及熟练度，保留观察不足层。 |
| 统计 | 候选双侧α=0.05、功效80%；预登记主指标、Δ、护栏容忍范围与停止规则，报告效应量和置信区间；重复观测按用户聚类/重采样，多重比较校正。 |
| 节奏 | 先事件回放及A/A健康检查，再小范围和扩灰。候选观察至少两个完整周周期且满足样本量；安全故障立即停。比例与日期按资源和流量确定。 |

同时期随机对照，监测SRM分组异常、版本、可用歌曲、热点活动、新奇效应与数据丢失。[W08] 不只比较功能使用者与未使用者，不按实验后行为挑人或删除不利结果。

扩灰条件：达到预定最小业务改善，置信区间支持方向，护栏不过线，隔离和权限校验通过。收益与成本或多样性冲突时继续迭代；不显著不等于完全无效。

两组等样本连续指标初估：`n≈2×(z₁₋α/₂+z₁₋β)²×σ²/Δ²`，再按分布、聚类和流失校准。当前无业务基线，不给出虚构样本量或实验结果。

## 17｜后续需求与投入

**R05：历史影响管理。** 最近播放中选择具体记录或时间段，排除普通播放、时长、跳过及其派生长期特征；保留历史展示、独立收藏等操作。同歌其他时间的正常播放不自动排除，也不删除整个歌手/曲风。聚合特征需来源追溯及异步重算，区分已标记、修正中、完成、失败；撤销恢复该批资格并重算，不承诺即时回滚模型。

**R06：手势快捷入口。** 比较歌曲列表左滑少推与现有更多入口。手势只作辅助，保留按钮和无障碍路径，分别测试切歌与系统返回冲突；先验证高频负反馈用户的重复操作成本。

| 模块 | 预期价值与投入 | 取舍 |
| --- | --- | --- |
| R03 | 降低表达成本；客户端、偏好与推荐集成，投入中。 | 优先验证主链路，真实覆盖率未知。 |
| R04 | 保护情境性收听；事件到特征全链路，投入中高。 | 信任边界优先，不能按一个开关估算成本。 |
| R05 | 事后补救；溯源与重算，投入高。 | 依赖不足，延后。 |
| R06 | 减少重复步骤；投入低至中。 | 收益和冲突待测，延后。 |
| R07 | 多条件表达；额外解析、评估与服务成本。 | 独立实验，不拖累R03/R04。 |

补充资料：真实任务/访谈、W3原报告、反馈原始出处；需要核对当前客户端时补设备、版本、地区及录屏。真实集成另需事件/特征链路、有效收听定义和实验基线。
