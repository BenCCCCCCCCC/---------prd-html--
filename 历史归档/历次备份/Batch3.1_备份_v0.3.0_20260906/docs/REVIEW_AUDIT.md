## 2. 自审中主动修正的问题

1. 不再把精准偏好、探索、新手、临时情境硬分成四个互斥人群；频率、强度、年龄阶段与熟练度分别记录。
2. 原问卷的App使用频率不能直接说成推荐使用频率；28天观察不足与分母为0单列。
3. R03仅本次的少推不应因为“显式意图”就自动写长期；将R04事件表按scope拆开。
4. 到期提醒不静默解除保护；没有采用老师举例的自动关闭，而是写明替代方案和原因。
5. 少推、屏蔽、历史事件排除是三种不同对象；不宣传“少推后绝不出现”。
6. 没有内部有效收听定义时，不能仅写“沿用平台定义”就算可测；演示阈值明示为可改参数。
7. 调整者内部的有效收听率有自选择偏差，保留诊断用途，实验另定义所有随机分配用户日的主指标。
8. 去掉未校准模型置信度0.89；局部规则模拟不伪称真实AI。JSON合法与语义保真分开验。
9. 不再让R05/R06自动膨胀成首版功能；R03加入最小长期偏好管理是为了让“长期可控”可逆。
10. 设置保存与推荐展示分开；失效、旧响应、撤销冲突、歌曲快照和中途切片均写清。
11. 没有把全部Figma同步作为已完成事项；已检查节点与未检流程分别登记。
12. 长期写入同字段会清理旧会话覆盖，检查合并后冲突；已有本次方案转长期必须额外确认差异，避免“保存了却看不到变化”。
13. 修正“低频用户每周末听歌”的例子：每周一次可能已落入中频；改成28天只听1–3天但单次长时，案例与定义保持一致。
14. 用可对比的配色Token替代“高级感”；主按钮改用能支持白字对比的深红；不靠缩小字体塞页面。

## 3. 已完成的检查与尚未执行

- 未执行：任何应用运行时自动化、40条解析器/模型评估、真实用户任务、全部Figma跳转、公开部署/跨浏览器实际体验。验收与AI用例仍为not_run。
- 注意：固定排序预期来自规格计算，只是测试夹具，不是已经在应用运行的效果。Token对比是数学检查，不能替代实际页面可访问性审核。

## 4. 已完成的方案取舍补充

- 新增 T01–T08 方案比较：不仅记录“做什么”，还记录候选 A/B/C、判断标准、为什么采用 B、选择代价和验证/反转条件。
- 明确“未采用”表示当前目标与证据下不进入首版；“延后”表示可能有价值，但需要先获得证据或解除依赖。
