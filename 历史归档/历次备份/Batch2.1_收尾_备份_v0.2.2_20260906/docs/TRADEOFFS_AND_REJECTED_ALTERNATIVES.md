# 方案取舍与未采用方案

版本：v0.1 / 2026-09-05 / 已批准进入 Batch 2 本地 Beta。

本文件记录“为什么没有做另一种方案”，供 PRD 评审、作品集深读和面试追问使用。它不是失败清单，也不表示这些方案永久错误；每项结论都受当前证据、求职展示目标和首版开发范围约束。

## 1. 展示原则

- PRD：保留完整方案 A/B/C、选择理由、付出的代价和后续验证方法。
- HTML 90 秒层：只展示 3 个最能代表产品判断的取舍，每张卡先写“采用什么”，再展开“为什么不选其他方案”。
- HTML 深读层：展示全部主要取舍，并区分“未采用”与“延后”。
- 简历：不罗列全部被否决方案，只用一句话体现范围与取舍；面试时再展开。
- 设计方案比较统一称为“方案 A/B/C”；实验分组统一称为“A/B 对照实验”，避免把两者混淆。
- 不使用虚构的 8.7/10、ROI 92 分等精确评分。没有真实数据时，采用定性标准和可验证假设。

## 2. 主要方案取舍

### T01｜用户分层：为什么不继续只写高频/低频

**问题：** 怎样解释不同用户为什么需要不同的推荐控制？

| 方案 | 内容 | 结论 |
|---|---|---|
| A | 只按高频/低频划分 | 未采用。频率只能说明接触机会，不能解释精准偏好、探索意愿、控制熟练度和临时情境。 |
| B | 频率、强度、新老程度、推荐依赖、控制熟练度、当前意图和情境分轴 | **采用。** 能解释“同样高频但需求相反”，也能形成招募和分析口径。 |
| C | 直接制作带姓名、照片、收入的三张 Persona | 未采用。当前没有真实访谈原始数据，细节会变成虚构用户。 |

**选择 B 的代价：** 文档和测试记录更复杂，需要维护多个维度与缺失值。

**验证：** 首轮可用性测试覆盖相似频率但不同意图、相似意图但不同熟练度的用户，观察是否出现不同任务失败。

### T02｜入口形态：为什么选择轻量 Bottom Sheet

**问题：** 如何把分散的推荐控制能力放到用户当下听歌的路径中？

| 方案 | 内容 | 结论 |
|---|---|---|
| A | 新建独立“推荐控制中心” | 未采用。信息完整，但入口更深、学习成本和页面范围更大，首版难以验证“当下纠偏”是否成立。 |
| B | 在推荐来源和播放页保留可见入口，使用 Bottom Sheet 聚合“想听 / 不想听 / 影响范围” | **采用。** 与当前任务靠近，复用现有页面，能在不重做首页的情况下形成完整链路。 |
| C | 以左滑/长按手势作为主要入口 | 延后为 R06。效率可能更高，但不可发现，且可能与系统返回或播放器手势冲突。 |

**选择 B 的代价：** 弹层空间有限，需要把复杂设置分层；不能一次展示所有规则。

**验证：** 测首次独立找到入口、完成时间、返回/取消是否误操作，以及 200% 文字缩放下主操作是否可达。

### T03｜首版范围：为什么不是全部功能一起做

**问题：** 首版应该同时实现多少需求？

| 方案 | 内容 | 结论 |
|---|---|---|
| A | R03、R04、R05、R06、R07 全部实现 | 未采用。需求与技术面过宽，无法判断效果来自哪个能力，也会稀释核心叙事。 |
| B | R03/R04 为核心，R07 为可移除实验；R05/R06 只定义边界并延后 | **采用。** 既形成“控制—保护—AI候选”的完整展示，又保持可测试和可解释。 |
| C | 只做 R03，不做临时收听和 AI | 未采用。开发更轻，但无法回答长期画像污染与 AI 产品经理能力边界。 |

**选择 B 的代价：** 仍需同时维护确定性产品状态和一条 AI 候选链路。

**验证：** 每个模块有独立通过条件；R07 失败时 R03/R04 仍可完整使用。

### T04｜控制模型：为什么把“仅本次”和“临时收听”拆开

**问题：** 一个开关能否同时表达“本次设置保存多久”和“普通行为是否参与长期学习”？

| 方案 | 内容 | 结论 |
|---|---|---|
| A | 合并成一个“不影响推荐”开关 | 未采用。用户无法知道它控制显式设置、隐式行为还是两者；研发也难定义事件边界。 |
| B | `仅本次 / 长期偏好`控制显式设置保存范围；`临时收听`独立控制普通播放、时长和跳过是否用于长期学习 | **采用。** 两个问题分别可解释、可测试、可撤销。 |
| C | 所有调整都只在当前会话生效，不提供长期保存 | 未采用。降低风险，但无法满足用户明确希望长期保存的偏好。 |

**选择 B 的代价：** 比单开关多一个概念，必须通过短文案、四种组合和可用性测试降低理解负担。

**验证：** 让参与者复述四种组合；若多数人把两个控制混为一谈，优先调整结构和文案，而不是增加教学。

### T05｜负反馈强度：为什么“少推”不等于黑名单

**问题：** 如何既允许纠偏，又避免一次操作永久收窄推荐？

| 方案 | 内容 | 结论 |
|---|---|---|
| A | 所有负反馈直接加入黑名单 | 未采用。反馈强度过高，容易因临时反感造成长期损失，也会降低探索空间。 |
| B | 软性“少推”与强性“黑名单”分开；首版黑名单只读说明 | **采用。** 用户预期清楚，允许轻度纠偏，同时保留强约束。 |
| C | 只提供跳过，不增加明确负反馈 | 未采用。成本最低，但系统只能继续猜测，无法验证显式纠偏价值。 |

**选择 B 的代价：** 需要更清楚地解释“仍可能出现”，并处理同一标签的正负冲突。

**验证：** 测用户是否理解少推后仍可能出现，以及是否能在不想永久屏蔽时选择正确操作。

### T06｜临时收听到期：为什么不在 4 小时后静默关闭

**问题：** 如何兼顾忘记关闭与不知情恢复长期学习？

| 方案 | 内容 | 结论 |
|---|---|---|
| A | 4 小时后自动关闭保护 | 未采用。能减少遗忘，但可能在用户无感知时重新开始学习后续播放。 |
| B | 到提醒点进入 `review_required`，继续保护，要求用户选择继续或关闭 | **采用。** 不阻断听歌，也不静默放行数据。 |
| C | 永不提醒，只允许手动关闭 | 未采用。最保守，但长期遗忘的风险和状态负担更高。 |

**选择 B 的代价：** 增加一次确认和常驻状态设计；提醒频率仍需真实测试校准。

**验证：** 测用户在提醒时能否判断当前是否仍受保护，以及是否误以为关闭后会追溯回填此前事件。

### T07｜R07 实现：为什么公开首版不直接接真实 LLM

**问题：** 如何在公开求职作品集中展示 AI 产品能力，同时保证稳定、成本和权限安全？

| 方案 | 内容 | 结论 |
|---|---|---|
| A | 首版直接调用真实 LLM | 未采用。存在密钥、成本、网络、输出漂移和长期维护风险；也可能把项目变成模型调用演示。 |
| B | 本地确定性解析器作为默认实现，保留真实模型 Adapter 契约但关闭 | **采用。** 可稳定复现 Schema、grounding、冲突、权限、修正和 Eval；以后可替换模型。 |
| C | 完全删除 AI 功能 | 未采用。主产品仍成立，但不能充分展示 AI 产品经理对能力边界和验证链路的设计。 |

**选择 B 的代价：** 不能声称已验证真实模型效果，语言覆盖能力有限，必须明确标注“本地规则模拟”。

**验证：** 运行合成用例和非法输出夹具；真实模型接入需另行批准，并与本地基线比较语义、权限、延迟和成本。

### T08｜公开叙事：为什么不补一个看起来更漂亮的成果数字

**问题：** 没有真实问卷和上线结果时，作品集如何建立可信度？

| 方案 | 内容 | 结论 |
|---|---|---|
| A | 使用模拟样本生成“30份有效问卷”“提升20%” | 未采用。会把课程练习和合成数据包装成真实结果，求职风险高。 |
| B | 标注 FACT / INFERENCE / HYPOTHESIS / SIMULATION；展示已完成、未证明和下一步 | **采用。** 不靠假数字，但能展示证据意识、验证设计和诚实边界。 |
| C | 完全删除研究和效果讨论，只展示界面 | 未采用。视觉更轻，但无法证明产品判断和 AI 边界。 |

**选择 B 的代价：** 首屏需要控制信息密度，且必须避免免责声明压过核心价值。

**验证：** 招聘者快速测试：90 秒内能否说清问题、三项决策、当前证据水平和下一步。

## 3. “未采用”与“延后”的区别

- 未采用：在当前目标和证据下，明确不作为首版方向，例如独立控制中心、直接真实 LLM、自动静默解除保护。
- 延后：可能有价值，但需要先取得证据或解决依赖，例如 R05 历史影响管理、R06 手势快捷入口、真实模型适配、公开部署。
- 任何延后项进入实施前，都要重新检查用户价值、范围、依赖、数据和当前行业状态，不能因为曾写进 PRD 就自动开发。

## 4. 面试回答模板

遇到“为什么选 B、不选 A”时，按五步回答：

1. **场景与目标：** 当时要解决什么问题，当前证据和资源是什么。
2. **候选方案：** A、B、C 分别是什么，不把最终方案伪装成唯一答案。
3. **判断标准：** 用户成本、可发现性、范围、实现依赖、风险、可验证性。
4. **决定与代价：** 为什么选 B，以及 B 带来的新问题。
5. **验证与反转条件：** 用什么数据或测试判断；出现什么证据时会改选 A/C。

简短示例：

> 我比较过独立控制中心、轻量 Bottom Sheet 和手势入口。首版选择 Bottom Sheet，不是因为它视觉更好，而是它最接近用户当下纠偏场景，能复用现有推荐与播放页，也便于单独验证入口和完成链路。代价是空间有限，所以我把复杂规则分层，并保留手势作为后续效率实验。若真实测试显示用户频繁重复操作且入口发现率已经稳定，我会重新评估手势方案。
## 5. 三类编号必须分开

- 演示任务：使用 `Demo 1/2/3`，分别代表主动调整、即时负反馈和临时收听。
- 设计比较：使用“方案 A/B/C”，回答为什么采用某个产品方案。
- 随机实验：使用“A/B 对照实验”，回答上线后是否存在因果效果。
