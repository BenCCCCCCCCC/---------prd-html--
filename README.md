## 版本与文件判断规则

以后只按下面的规则判断“哪个是最新的”：

1. **继续工作** → 只进入 `01_当前工程/`。
2. **查看某次正式交付** → 进入 `02_交付文件/<版本号>/`。
3. **找旧版本、旧备份、旧指令** → 进入 `99_历史归档/`。
4. 根目录不再新增 `Batch2`、`Batch3`、`Batch3.2` 这类并列工程文件夹。
5. 当前版本状态优先看本 README、`01_当前工程/README.md` 和 `01_当前工程/docs/HANDOFF.md`。
6. `01_当前工程/00_README.md`、`00_START_HERE.md` 属于早期启动材料，文件名虽然靠前，但**不作为当前版本状态入口**。

## 项目边界

当前仓库用于个人产品设计、作品集展示与本地原型验证。现有材料不代表网易云音乐官方方案，也不应被描述为已经上线的功能、真实业务增长结果或已完成的线上 A/B 测试。

原型中的数据、账号、音乐内容及 AI 相关能力以本地模拟和验证为主；如后续接入真实服务，应单独记录新的验证范围和版本。

## 后续维护约定

- 当前工程始终只有一份，不再复制出新的 `BatchX_完整工程` 放到根目录。
