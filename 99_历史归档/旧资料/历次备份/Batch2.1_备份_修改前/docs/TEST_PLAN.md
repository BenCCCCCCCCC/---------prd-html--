## 二、真人可用性测试：首轮计划8个席位

不是8个独立、互斥的画像。每人记录使用频率、收听强度、新老程度、推荐依赖、功能熟练度、当前任务；同一个人可覆盖多个维度。招募优先覆盖：

| 席位 | 优先覆盖 | 不预设的结论 |
|---|---|---|
| U1 | 高频、短时、精准偏好 | 高频不一定重度 |
| U2 | 高频、长时、探索 | 探索不等于喜欢一切 |
| U3 | 低频、长时、熟练 | 低频不代表不需要控制 |
| U4 | 存量用户、控制新手 | 老用户不一定会用设置 |
| U5 | 新使用者、观察窗口不足 | 不强行归低频 |
| U6 | 临时共听/借设备情境 | 不把情境当永久画像 |
| U7 | 相似频率但相反探索意愿 | 观察意图差异 |
| U8 | 相似意图但不同熟练度 | 观察引导差异 |

8只是资源可控的一轮招募计划；不能推算市场比例。出现新的严重问题时补相应类型，连续发现重复问题可用于排修优先级，但不是统计饱和证明。不要全部只找设计/技术同学，也不要让所有人先看教学视频。

## 三、任务脚本

开场：这是概念原型，不是测试你的能力。可随时停止。仅在明确同意后记录观察；不收集真实音乐账号、年龄收入等与当前任务无关的信息。

T1：现在推荐方向不合适，你想多听新的民谣，但不改变以后的固定偏好。请自己完成。观察入口、标签、范围、确认与结果理解。不要直接告诉TA点击哪个按钮。

T2：你不想经常听到当前音乐人，但并不是永远不能再听。请调整，然后撤销。问TA是否仍可能遇到，不提示“少推”答案。

T3：接下来给朋友放歌，但不希望这些普通播放影响你以后的推荐。请设置，再切换到歌单来源。观察是否理解持续生效及红心例外。

T4：时间推进到提醒点。请判断当前是否还受保护，并选择结束。询问此前收听是否会补回推荐，是否删除了历史。

T5：先手动完成三个条件，再通过R07完成同样条件；交错任务顺序，避免总是先教手动再测试AI。用无真实个人信息的输入。比较用时、修正、理解，不将规则模拟结论推广成真实LLM表现。
